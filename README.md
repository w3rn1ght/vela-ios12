# Vela

VPN-клиент для джейлбрейкнутого iOS 12: список серверов, подписки, пинг, выбор
ноды и настоящий туннель на `utun` — без `NetworkExtension` и без App Store.

Под капотом — ядро [sing-box](https://github.com/SagerNet/sing-box) (форк
[sing-box-lx](https://github.com/Leadaxe/sing-box-lx)), которое root-демон
запускает как отдельный процесс и заворачивает в `utun` сплит-маршрутами.

```
┌───────────┐   unix socket    ┌────────┐   fork    ┌──────────┐
│ Vela.app  │ ───────────────► │ velad  │ ────────► │ sing-box │
│  (UIKit)  │  JSON, cmd/ответ │ (root) │           │          │
└───────────┘                  └───┬────┘           └────┬─────┘
                                   │                     │
                                   │ route add           └─► utunN ─► туннель
                                   └─► 0.0.0.0/1, 128.0.0.0/1 ─► utunN
```

## Возможности

- **Протоколы:** VLESS (TLS, REALITY, XHTTP, WS, gRPC, HTTP/2, HTTPUpgrade),
  VMess, Trojan, Shadowsocks, Hysteria2, TUIC v5.
- **Подписки:** обычный `https://…` (base64, plain-список, Xray-JSON), заголовки
  HWID для панелей Remnawave и совместимых.
- **Happ-ссылки.** `happ://crypt/crypt2…crypt5/…` расшифровываются в приложении и
  превращаются в обычную подписку — вставлять можно как есть.
- **Список серверов:** импорт, дедупликация, сохранение между запусками и
  обновлениями пакета, выбор активной ноды, TCP-пинг параллельно с привязкой к
  физическому интерфейсу.
- **Автоподбор** (🔍): перебирает ноды по пингу и проверяет реальный трафик через
  туннель, а не только TCP-доступность.
- **Диагностика в приложении:** состояние демона, лог ядра, проверка DNS и
  доступности узлов без SSH.
- **iPad:** интерфейс и ландшафтная ориентация.

## Требования

- iPhone или iPad на **arm64**, iOS **12.0–12.5.x**.
- Джейлбрейк с работающим `launchd` (unc0ver, checkra1n, Chimera и т. п.).
- Root-доступ для установки `.deb`. Вариант `.ipa` ставится как обычное
  приложение, но без демона туннель не поднимется — нужен именно пакет.

## Установка

### .deb (рекомендуется)

```bash
scp com.vela.vpn_<версия>_iphoneos-arm.deb root@device:/var/root/
ssh root@device
dpkg -i /var/root/com.vela.vpn_<версия>_iphoneos-arm.deb
uicache -p /Applications/Vela.app
```

`postinst` создаёт каталоги, выставляет права, загружает LaunchDaemon
`com.vela.daemon` и обновляет иконку. При обновлении поверх старой версии список
серверов и подписка сохраняются — состояние чистится только при `dpkg -P`.

Проверка после установки:

```bash
launchctl list | grep vela
ls -l /var/mobile/Library/Vela/      # nodes.json, control.sock, core.json, core.log
```

### .ipa

Собирается в том же релизе (`Vela-<версия>.ipa`) и ставится любым
подписывающим/установочным инструментом. Содержит только приложение.

## Использование

1. **＋** → вставить ссылку на ноду или `https://…` подписку → «Добавить».
2. Тап по строке — нода выбрана (галочка).
3. Потянуть список вниз — пинг всех нод (параллельно, по 6 за раз).
4. **Подключить** — статус в шапке: нода, протокол, `utun`, время пробы.
5. **Лог** — отчёт о подписке, состояние демона и лог ядра.
6. 🔍 — автоподбор рабочей ноды.
7. ⚙ — HWID, обновление подписки, сброс маршрутов, диагностика.

Список нод, выбранная нода и ссылка на подписку сохраняются автоматически.

## Поддерживаемые ссылки

| Схема | Протокол | Примечания |
|---|---|---|
| `vless://` | VLESS | TLS, REALITY, XHTTP, WS, gRPC, HTTP/2, HTTPUpgrade, `flow=xtls-rprx-vision` |
| `vmess://` | VMess | base64-JSON (v2rayN), WS/gRPC/HTTP2/TCP, TLS |
| `trojan://` | Trojan | TLS, WS, gRPC |
| `ss://` | Shadowsocks | оба формата ссылок, `obfs-local`, `v2ray-plugin` |
| `hysteria2://`, `hy2://` | Hysteria2 | TLS, `obfs=salamander` |
| `tuic://` | TUIC v5 | `uuid:password` |
| `https://…` | подписка | base64, plain-список, Xray-JSON |
| `happ://crypt…` | подписка Happ | расшифровывается в приложении |
| `happ://add/<url>` | подписка Happ | разворачивается в `https://…` |

Не поддерживаются: TUIC v4 (`token=`), VMess с HTTP-обфускацией и mKCP,
профили маршрутизации `happ://routing/…`.

## Подписки с HWID

Панели Remnawave и совместимые привязывают подписку к устройству заголовком
`x-hwid`. Без него вместо нод возвращаются заглушки
`vless://000…@0.0.0.0:1` с просьбой включить передачу HWID.

Vela генерирует UUID один раз, хранит его локально и отправляет вместе с
`x-device-os`, `x-ver-os`, `x-device-model` и User-Agent v2rayNG. Текущий HWID
виден в ⚙ — его можно передать провайдеру или заменить на выданный.

Если подписка вернула пустой список, приложение показывает отчёт: HTTP-код,
размер, формат ответа и первые строки. Тот же отчёт лежит в
`/var/mobile/Library/Vela/last-subscription.txt`.

## Как это работает

- **Демон.** `velad` слушает unix-сокет `/var/mobile/Library/Vela/control.sock`,
  принимает JSON-команды (`start`, `stop`, `status`, `probe`, `ping`, `log`,
  `cleanup`), запускает ядро от root и следит за ним.
- **Маршруты.** Сплит-дефолт `0.0.0.0/1` и `128.0.0.0/1` уходят в `utunN`;
  сервер прокси получает host-маршрут мимо туннеля, иначе получается петля.
  IPv6 по умолчанию не заворачивается: без рабочего v6-транспорта iOS считает
  сеть мёртвой и уходит на LTE.
- **DNS.** Ядро поднимает слушатель на `127.0.0.1:53`, а демон на время
  подключения переключает системный резолвер на него. Запросы попадают в
  DNS-модуль ядра (`hijack-dns`) и резолвятся через туннель — имена, заблокированные
  провайдером, работают так же, как остальной трафик. При отключении резолвер
  возвращается на прежний.
- **Проверка.** После старта демон делает реальный HTTP-запрос через туннель:
  `connect()` ничего не доказывает, gvisor принимает хендшейк даже при мёртвом
  прокси.

## Сборка из исходников

Нужны macOS (или Linux с Theos), Xcode Command Line Tools, Go 1.25+, Theos и
`ldid`.

```bash
git clone https://github.com/w3rn1ght/vela-ios12.git
cd vela-ios12

./scripts/build-core.sh        # ядро sing-box-lx под ios/arm64, min iOS 12.0
./scripts/run-parser-tests.sh  # офлайн-тесты парсера и сборки конфига
export THEOS=~/theos
make package                   # -> packages/com.vela.vpn_<версия>_iphoneos-arm.deb
```

`.ipa` собирается из `.theos/_/Applications/Vela.app` обычным zip в `Payload/`.
Готовые `.deb` и `.ipa` собирает GitHub Actions на каждый push.

Иконки пересобираются скриптом `scripts/make_icon.py` (чистый Python, без Pillow).

## Диагностика

| Что | Где |
|---|---|
| Лог демона | `/var/mobile/Library/Logs/Vela/daemon.log` |
| Лог ядра | `/var/mobile/Library/Vela/core.log` |
| Конфиг ядра | `/var/mobile/Library/Vela/core.json` |
| Ноды | `/var/mobile/Library/Vela/nodes.json` (0600) |
| Отчёт о подписке | `/var/mobile/Library/Vela/last-subscription.txt` |
| Маршруты | `netstat -rn \| head -20` |
| Подпись бинарей | `ldid -e /usr/libexec/vela/sing-box` |

Типичные случаи:

- **«Демон не отвечает»** — `launchctl list | grep vela`; сокет должен быть
  `srw-rw-rw-`.
- **«Ядро не создало tun»** — смотрите `core.log`. Ручной запуск для проверки:
  `/usr/libexec/vela/sing-box run -c /var/mobile/Library/Vela/core.json`.
- **«Не удалось поставить маршруты»** — демон должен работать от root.
- **Нет интернета после падения ядра** — ⚙ → «Сбросить маршруты»; демон также
  снимает `0/1` и `128/1` при старте и по `SIGTERM`.
- **Подписка отдаёт заглушки** — исчерпан лимит устройств, см. раздел про HWID.

## Ограничения

- Одна активная нода; смена ноды применяется переподключением.
- Нет kill switch и автоматической переустановки маршрутов при смене Wi-Fi ↔ LTE.
- Пинг — TCP-хендшейк до `server:port`, а не полный URL-test через прокси.
- IPv6-серверы поддерживаются частично.

## Безопасность

Инструмент предназначен для подключения к **своим** серверам. Ссылка на
подписку — bearer-токен: она даёт доступ к вашему списку нод и трафику, не
публикуйте её. Состояние хранится в `/var/mobile/Library/Vela` с правами `0600`.
